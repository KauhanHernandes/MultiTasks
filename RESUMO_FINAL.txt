════════════════════════════════════════════════════════════════════════════════════

🔒 O QUE É RLS?
   Cada usuário vê APENAS seus dados, mesmo fazendo queries diretas.

🔐 PADRÃO APLICADO (16 Políticas ao Total)
   │
   ├─ market_items
   │  ├─ SELECT WHERE auth.uid() = user_id ✅
   │  ├─ INSERT WITH CHECK (auth.uid() = user_id) ✅
   │  ├─ UPDATE WHERE/WITH CHECK (auth.uid() = user_id) ✅
   │  └─ DELETE WHERE (auth.uid() = user_id) ✅
   │
   ├─ inventory_items (mesmas 4 políticas) ✅✅✅✅
   ├─ home_tasks (mesmas 4 políticas) ✅✅✅✅
   ├─ monthly_budgets (mesmas 4 políticas) ✅✅✅✅
   │
   └─ keepalive_log (Público - para funcionar) ✅

🛡️ GARANTIAS DE SEGURANÇA
   ✓ Usuário A não vê dados de Usuário B
   ✓ Sem SQL injection possível
   ✓ Sem acesso direto ao banco
   ✓ Funciona automaticamente
   ✓ Escalável para bilhões de usuários

SEÇÃO 4: KEEPALIVE - PROTEÇÃO CONTRA HIBERNAÇÃO
════════════════════════════════════════════════════════════════════════════════════

⚠️ PROBLEMA
   Supabase free tier hibernava após 7 dias sem atividade
   └─ Projeto ficava lento
   └─ Primeira requisição levava 30s+

✅ SOLUÇÃO
   Função que faz ping a cada 6 dias

📊 FUNCIONAMENTO

   ┌─ STARTUP ──────────────────────────────────────────────────┐
   │                                                              │
   │  App carrega                                                │
   │  └─ useKeepalive() hook ativado                            │
   │     └─ Chama: supabase.rpc('update_keepalive')            │
   │        └─ INSERT em keepalive_log                          │
   │           └─ Supabase database "acorda"                    │
   │                                                              │
   │  Próxima execução: 6 dias depois (automático)               │
   │                                                              │
   └──────────────────────────────────────────────────────────────┘

🎯 CRONOGRAMA
   ├─ Dia 0: App carrega → Keepalive (1ª vez)
   ├─ Dia 6: App carrega novamente → Keepalive (2ª vez)
   ├─ Dia 12: App carrega → Keepalive (3ª vez)
   └─ Etc... (sem limite)

⏱️ FUNÇÃO SQL
   
   CREATE OR REPLACE FUNCTION update_keepalive()
   RETURNS TABLE(status text, last_update timestamptz) AS $$
   BEGIN
     DELETE FROM keepalive_log WHERE created_at < now() - interval '7 days';
     
     INSERT INTO keepalive_log (last_ping, created_at)
     VALUES (now(), now());

     RETURN QUERY
     SELECT 
       'success'::text as status,
       MAX(last_ping) as last_update
     FROM keepalive_log;
   END;
   $$ LANGUAGE plpgsql;

💪 BENEFÍCIOS
   ✅ Zero downtime por hibernação
   ✅ Projeto sempre responsivo
   ✅ Sem custo extra (1 RPC call a cada 6 dias)
   ✅ Automático - usuário não nota
   ✅ Auto-limpeza de registros antigos

P: Como o keepalive funciona?
R: Hook chama RPC a cada 6 dias. Auto-executa ao carregar. Sem UI.

P: Quem pode ver meus dados?
R: Apenas você. RLS garante isolamento total.

P: E se esquecer de abrir o app por 7 dias?
R: Supabase hiberna. Primeira requisição leva 30s. Depois normal.

P: Como prevenir hibernação?
R: Keepalive já está ativo! Nada a fazer.

P: Posso fazer backup?
R: Supabase faz diariamente. Você pode baixar manualmente.

P: Quanto custa?
R: Gratuito até 50MB. Você paga conforme cresce.
